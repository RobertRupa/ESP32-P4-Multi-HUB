# P4 HMI and Wi-Fi Wizard Audit

## Scope

- Board: Guition JC4880P443C_I_W, P4 silicon revision 3.2, `/dev/ttyACM0`.
- Host/radio: ESP-IDF v5.5.5; ESP-Hosted host and integrated C6 both report 3.1.0 over SDIO RPC v2.
- Current RSSI-diagnostics build: `firmware/p4/build/hub_p4_esp_hosted_host.bin`, SHA-256 `24d96656a7136639002385fd0d8b34801e5e3b047a4e9cade5b9a04a69ee53a9`, 1,218,288 bytes; encrypted app-only flash completed.
- User explicitly approved NVS encryption and irreversible eFuse programming. Hardware eFuse summary before transition showed Flash Encryption disabled and `SPI_BOOT_CRYPT_CNT=0`.
- No SSID or password is recorded in this audit.

## Implementation

- LVGL 9.5 touchscreen wizard uses the pinned `esp_lvgl_port` 2.9.0, `esp_lcd_st7701` 2.0.3 and `esp_lcd_touch_gt911` 1.2.1 components.
- ST7701S uses MIPI-DSI 2-lane, RGB565, 480x800 at 34 MHz; PHY LDO channel 3 at 2.5 V; board reset/backlight GPIO5/GPIO23. Vendor-specific panel initialization is based on the same-board public bring-up reference.
- GT911 is configured on the documented shared I2C bus GPIO7/GPIO8 at address 0x5D. Touch reset/interrupt GPIOs are left unassigned because the board references disagree and those lines are not required for this validated read path.
- Wi-Fi uses `esp_wifi_remote` 1.3.1 over ESP-Hosted; scan/connect calls run on a dedicated task with bounded command/event queues and a 16-network scan cap. The secure-storage build uses `wifi_keys` and `wifi_cfg` NVS partitions; credentials are written only after DHCP and only after Flash Encryption is active.
- The ESP-Hosted `eh_wifi` tag is raised to WARN before Wi-Fi configuration. A subsequent association reached DHCP without emitting the earlier INFO-level SSID configuration line.
- `system_diagnostics.hpp` provides the shared stateless snapshot used by the touchscreen and HTTP page for Flash Encryption and free PSRAM/internal heap metrics; it performs no I/O, allocation, persistence or secret access.
- The Wi-Fi owner task samples ESP-Hosted RSSI on connection and every 5 seconds. Only dBm and validity are copied to UI/HTTP snapshots; SSID/BSSID are not returned.

## Results

- Build: `idf.py build` passed for ESP32-P4 with encryption-sized bootloader and relocated table. Remaining warnings are upstream optional TinyUSB network-mode Kconfig warnings.
- Host regression tests: `capability_model_tests` passed (1/1); `device_registry_tests` passed (1/1).
- Hardware: boot log confirmed 32 MB HEX PSRAM at 200 MHz and PSRAM memory test OK; P4/C6 ESP-Hosted versions matched at 3.1.0; SDIO aggregation negotiated.
- LCD/touch: generic ST7701 initialization produced a black screen. After applying the same-board ST7701 register table, the user confirmed the wizard is visible and touch responds. GT911 runtime reported ID 0x393131, config version 250. The panel ID read command still returned `FF FF FF`; visual operation was user-confirmed.
- Wi-Fi: user selected the home network and reported success. Runtime emitted `IP_EVENT_STA_GOT_IP` and `esp_netif` reported DHCP IPv4. The SSID/password are not reproduced here. The `eh_wifi` tag is set to WARN before Wi-Fi setup; no SSID appeared in the successful reconnect log.
- Keyboard: user confirmed the final bottom-docked keyboard displays fully and accepts input without scrolling the page.
- Home dashboard: user confirmed the startup page is visible. It shows Wi-Fi state, IPv4, encrypted-storage readiness, saved-profile state and the diagnostics URL; Wi-Fi settings remain available through a scan action.
- System status: touchscreen page includes Wi-Fi/IPv4/RSSI, encrypted-store/profile status, Flash Encryption, free PSRAM and internal heap, plus refresh. After encrypted app-only update and reset, `/api/status` returned `rssi_valid=true`, `rssi_dbm=-65`, connected/saved/encrypted; `/` returned HTTP 200. The latest RSSI UI layout has not yet been visually confirmed.
- Devices: user confirmed the empty-state screen is OK. It reports no registered devices, an unstarted coordinator and unavailable discovery. No sample devices or pairing command are shown; this P4 app does not initialize H2 or expose pairing controls.

## Secure-storage transition

- New partition map: default `nvs` `0x12000/24K`, `phy_init` `0x18000/4K`, factory `0x20000/0x3F0000`, `c6_fw` `0x410000/2M`, `wifi_keys` `0x610000/4K` (encrypted flag), `wifi_cfg` `0x611000/24K`. Existing NVS/PHY offsets moved to fit the encryption-sized bootloader and table at `0x11000`; the old default NVS is not migrated. `c6_fw` offset is unchanged.
- Encryption build: Flash Encryption Development Mode is enabled; Secure Boot is disabled. Bootloader size is `0x8C90`, within the `0x11000` table offset.
- First encrypted boot initially failed to reach the application. Read-only `get_security_info` showed `BLOCK_KEY0` purpose `XTS_AES_128_KEY`, Flash Encryption disabled, and `SPI_BOOT_CRYPT_CNT=0`; ROM logs showed flash busy/invalid header. Recovery preserved the eFuse key, erased only old/new P4 metadata and Wi-Fi NVS regions, and left C6 `0x410000..0x610000` untouched. A no-reset monitor was attached before the next first boot.
- First boot recovery succeeded: bootloader logged `Flash encryption completed`, burned the encryption counter, reset, and the encrypted P4 app booted. Secure `wifi_keys`/`wifi_cfg` partitions were initialized.
- Wi-Fi persistence validation: user re-entered credentials on the touchscreen and confirmed `Connected and saved securely`. HTTP GET `/api/status` returned `connected`, `credential_store_ready=true`, `credentials_saved=true`, and `flash_encryption=true`. The P4 was then reset without reflashing; `/api/status` again returned connected/saved with an IPv4 address, confirming auto-reconnect from encrypted NVS. No SSID/password is included in source, logs, or this audit.
- HTTP diagnostics: `http://192.168.69.17/` returned HTTP 200; `/api/status` on port 80 serves read-only JSON with state, IPv4, RSSI, encryption/storage flags and free memory only, not SSID, BSSID or credentials. After the latest controlled P4 reset, status reported connected, `credential_store_ready=true`, `credentials_saved=true`, `rssi_valid=true`, and `flash_encryption=true`.

## Limitations

- Board PCB revision and electrical continuity were not independently verified.
- Touch reset and interrupt pins remain intentionally unused/unverified.
- Long-term RSSI stability, roaming, IPv6/mDNS and soak behavior remain untested. The onboard microSD was not initialized because ESP-Hosted already owns SDMMC and concurrent slot lifecycle safety is not established.
- Flash Encryption is Development Mode only; Secure Boot is disabled. Development Mode permits plaintext serial reflashing and is not production-secure.
- Zigbee, Matter, display rotation and production security are outside this validation.
